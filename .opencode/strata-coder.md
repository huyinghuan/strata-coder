# Strata Coder 协作规则

本节适用于拥有 MCP 委派工具的主模型。本地 Worker 收到任务后直接实现并运行检查，不再次委派自身。

1. 默认把边界明确的函数、小模块或具体修复交给本地 Agent。主模型负责需求澄清、设计、任务拆分、独立验收、补丁审查及集成；纯讨论和少量文档修改可直接完成。
2. 用户说“这个任务用主模型”“不要调用本地模型”“你直接写”等，当前任务直接实现，不调用 `submit_task`，也不转交其他 Agent。用户指定“只用本地模型”时，不可用或失败应如实说明。一次选择只影响当前任务，除非用户明确要求持续改变偏好。
3. 首次委派先调用 `get_capabilities`。OpenCode 中常见名称是 `strata_coder_get_capabilities` 等，使用客户端实际提供的工具名。确认当前仓库绝对路径在允许范围内，并确认项目对应的检查名称；不要把演示项目的 `demo_unit` 用于本仓库。
4. 本机 OpenCode 安装为本仓库配置了 `strata_unit`：在任务副本内按锁文件安装依赖，然后运行 `test/*.test.js`。提交时显式传 `check_names: ["strata_unit"]`。其他机器先配置等价检查，以 `get_capabilities` 返回为准；检查缺失时先修复配置，不通过 `requireChecks:false` 绕过验证。
5. `workspace` 使用当前仓库的真实绝对路径；`task` 和 `acceptance` 描述行为、边界条件、兼容性要求及必要文件。`allowed_paths` 使用具体相对文件或目录前缀，不支持 glob；仅开放任务需要的路径。需要新增测试时明确允许对应测试文件，避免让修复实现的任务随意改动既有验收。
6. 每个新任务使用新的 `request_id`，仅对同一参数的超时重试复用该 ID。保存返回的 `task_id`，用 `get_task(wait_seconds=20)` 等待，不重复提交，不每秒轮询。同一仓库串行委派。
7. `ready_for_review` 表示副本中的结果待审查，原仓库尚未改变。核对 `verification`、检查结果、变更文件和验收条件，按需调用 `read_artifact` 读取补丁，避免把所有日志拉入主模型上下文。
8. 审查后在原仓库执行 `git apply --check <patch>`，通过后再 `git apply <patch>` 并运行项目测试。应用冲突时重新评估，不能覆盖用户的新修改。测试通过也不能代替补丁审查。
9. `needs_primary`、`failed`、`cancelled`、`interrupted` 都是终态。读取原因及必要的部分补丁，按用户偏好由主模型接手或拆小任务；不要更换 ID 原样无限重试。每个新任务会重新快照原仓库，不继承上一任务副本。
10. 用户中途要求接手时，停止新委派；取消本任务仍在运行的 Worker，并查询确认终态后再接手。禁用或断开 MCP 不会自动停止 Worker，不要取消其他任务。

## 宿主版本

- 使用已发布的 npm 版本作为宿主的编码 Agent，来开发本仓库。保持宿主已安装版本与被修改源码独立：测试运行的是任务副本中的源码，修改仓库不会自动更新运行中的 MCP。不要自行把宿主入口切换到开发源码；只有用户明确要求测试未发布的 MCP 服务本身时才调整入口。
