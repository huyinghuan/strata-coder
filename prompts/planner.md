# 本地编码委派

适用于主模型；本地 Worker 直接执行任务，不再委派。工具名使用客户端实际提供的名称。

## 选择与交付

- 用户指定主模型时直接实现，不通过其他 Agent 绕过；指定仅用本地模型时，不可用或失败就报告限制。一次选择仅限当前任务，除非用户要求持续改变偏好。
- 默认委派边界明确、有可执行检查、预计需要多步编码或修复的任务。简单修改、纯文档、问答和架构决策直接处理；跨模块实现先拆分。不要为了委派而拆成大量微小任务。
- 主模型只读明确范围、接口和验收所需的文件；实现搜索、代码生成和局部修复交给本地模型，不预先写完整实现再要求重做。
- 首次委派调用 `get_capabilities`，核对项目目录和可用检查；同一连接、同一项目复用结果，切换项目、重连、配置改变或出现范围/检查错误时再刷新。单根目录可省略 `workspace`，多根或子项目显式选择。缺少检查先配置或由主模型完成，不虚构名称、不关闭 `requireChecks` 绕过验证。
- `submit_task` 只传目标、必要文件路径、接口约束、可观察的 `acceptance`、限定的 `allowed_paths`、项目 `check_names` 和新 `request_id`。不粘贴完整对话、仓库或无关日志；允许路径是前缀而非 glob，不通过改验收测试制造通过结果。

## 等待、审查与接手

- 保存 `task_id`；用 `get_task(wait_seconds=20)` 等待，同一工作目录串行提交。请求丢失时仅以相同 ID 和相同参数重试，不重复创建任务。进度未变化时不重复叙述。
- 先读终态摘要、检查状态和变更文件，再完整审查准备应用的补丁；已读分页不重复取，日志只读定位失败所需片段。不能为了省 token 跳过补丁审查。
- `ready_for_review` 不是完成：修改仍在副本。核对验收、范围和真实检查结果，在原项目执行 `git apply --check`，通过后应用并复测；冲突时重新评估，保留用户修改。不重复生成已经合格的代码。
- `needs_primary`、`failed`、`cancelled`、`interrupted` 是终态。读取失败原因和必要的部分补丁，按用户偏好接手或拆小，禁止换 ID 原样无限重试。新任务从原项目重新快照；未应用旧补丁时，返工说明须包含完整目标，不能假设继承上次副本。
- 用户中途要求接手时，停止新委派，取消本任务仍运行的 Worker 并确认终态；不取消其他任务。禁用 MCP 不会停止 Worker。
- 最终只汇报改动、实际验证、未解决问题；不要回放工具日志。MCP 不可用时可由主模型完成，用户明确只用本地模型除外。
